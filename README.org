* Intro

This package lets you browse Reddit in Emacs org-mode.

It also lets you vote, reply, edit, delete, and submit posts.

Image posts, galleries and video posters are downloaded in the
background and shown inline; see [[*Images][Images]] and [[*Videos][Videos]].

Reddit requests now require a logged-in browser session for these actions.

~reddigg.el~ talks to a small local Python server, which Emacs starts
automatically as a subprocess.

The server relays each request to a userscript running in your logged-in Reddit tab.

#+begin_example
Emacs  <--HTTP-->  server/reddigg_server.py  <--websocket-->  userscript in Reddit tab
#+end_example

The tab performs the request with your own session, so no API keys are needed.
* breaking change version 0.9.0: no longer depends on ~browser-gt~
use ~browser-gt~ branch if you prefer it.

* Requirements

- Emacs 26.3 or later.
- ~promise~ 1.1 or later.
- ~ht~ 2.3 or later.
- ~org~ 9.2 or later.
- [[https://docs.astral.sh/uv/][uv]] (or an existing =server/.venv=) to install and run the
  server's dependencies from ~server/pyproject.toml~.
- A userscript manager such as Tampermonkey or Violentmonkey.
- A logged-in Reddit session in the browser.
- Optional: a video player such as ~mpv~ for =reddigg-play-video~, and
  librsvg for the play badge drawn onto video posters.

* Setup

1. Install the required Emacs packages.
2. Install ~userscript/reddigg-ws.user.js~ in your userscript manager.
3. Log in to Reddit and open an ~old.reddit.com~ tab.
4. Allow the connection when the browser prompts for permission.
5. Check that the toggle button at the bottom right corner shows connected.
6. Load ~reddigg.el~ in Emacs.
7. Run ~M-x reddigg-ping~ to check the whole chain.

The server starts automatically as an Emacs subprocess on the first
request; there is no separate server to launch by hand.
If you want to control it explicitly, use ~M-x reddigg-server-start~
and ~M-x reddigg-server-stop~.  A server that was already running is
reused and never stopped by Emacs.

The browser asks for permission because the userscript connects to ~127.0.0.1~.

Choose to always allow it, or the prompt returns on each page load.

The server listens on ~127.0.0.1:1979~ only.

When Emacs starts the server, the port comes from ~reddigg-server-url~;
if you start the server manually, use ~--port~ and change ~reddigg-server-url~
to match.

The userscript uses port 1979 unless the page URL has ~?reddigg_ws_port=PORT~.

* Server and userscript

The server creates a secret token in =~/.config/reddigg/token= on first start
(normally triggered by Emacs).

~reddigg.el~ reads it and sends it in the ~X-Bridge-Token~ header.

Set ~REDDIGG_TOKEN_FILE~ to use a different token file.

The userscript adds a button that shows the connection state: grey is connecting, green is connected, orange is reconnecting.

Click the button to toggle the connection to the server.

The server accepts websocket connections from ~reddit.com~ origins only.

Use ~--origin~ to allow others, ~--repl~ for an interactive prompt, and ~-v~ for debug logs.

If several tabs are connected, the most recently active one is used.
Tabs announce themselves when they open and when they become visible,
and hidden tabs stop refreshing their heartbeat, so that is the tab you
last looked at.

The userscript only ever fetches reddit itself, and it gives up on a
request after 25 seconds instead of holding the server until its own
timeout.

* Buffers

~*reddigg-main*~ shows your subreddit list.

~*reddigg*~ shows posts from a subreddit.

~*reddigg-comments*~ shows comments for a post.

The buffers use org-mode.

Enter on a Reddit link to run its Emacs command.

* Variables

~reddigg-subs~ lists the subreddits for ~*reddigg-main*~.

~reddigg-server-url~ is the server's base URL.

The default is ~http://127.0.0.1:1979/reddigg~. Its host and port are
also passed to the auto-started server, so changing it is all you need
to do to use another port.

~reddigg-token-file~ is the path to the server token.

The default follows ~REDDIGG_TOKEN_FILE~, then ~$XDG_CONFIG_HOME/reddigg/token~, then =~/.config/reddigg/token=.

~reddigg-server-autostart~ controls whether Emacs starts the server on
demand. The default is ~t~. Set it to ~nil~ to run the server yourself.

~reddigg-server-command~ overrides the command used to start the server.
It is a list of strings run in ~reddigg-server-directory~; ~%h~ and ~%p~
are replaced with the host and port from ~reddigg-server-url~.
The default prefers =server/.venv=, then ~uv run~, then ~python3~.

~reddigg-server-directory~ is where ~reddigg_server.py~ lives. The default
is the =server= directory next to ~reddigg.el~.

~reddigg-server-startup-timeout~ is how many seconds to wait for a newly
started server to accept connections. The default is 30.

~reddigg-server-stop-on-exit~ stops a server that Emacs started when
Emacs exits. The default is ~t~. Set it to ~nil~ if several Emacs
instances share one server.

~reddigg-request-timeout~ sets how many seconds Emacs waits for one request. The default is 35.

~reddigg-image-display~ controls image handling: ~inline~ (the default) downloads and shows images, ~link~ only shows a "show image" button, and ~nil~ disables them.

~reddigg-image-max-width~ is the maximum width in pixels for inline images. The default is 400. Set it to ~nil~ to use the original size.

~reddigg-image-cache-dir~ is where downloaded images are cached. The default is =~/.cache/reddigg/images=.

~reddigg-image-max-size~ is the largest image, in bytes, that reddigg will download. The default is 20 MiB.

~reddigg-image-timeout~ is how many seconds an image download may take. The default is 30.

~reddigg-video-player~ is the program ~reddigg-play-video~ runs to play a video.
The default is ~mpv~. Set it to ~nil~ to open videos in a browser instead.

~reddigg-video-player-args~ is a list of extra arguments for that program.
The default is ~nil~; the arguments are placed before the video URL.

~reddigg-video-poster-badge~ controls whether a play badge is drawn onto inline video posters. The default is ~t~.

* Commands

~reddigg-view-main~ shows your subreddit list.

~reddigg-view-sub~ prompts for a subreddit and shows its posts.

~reddigg-view-frontpage~ shows the front page from ~reddigg-subs~.

~reddigg-view-comments~ prompts for a post and shows its comments.

~reddigg-open-url~ opens a full Reddit post link in reddigg.

~reddigg-submit-post~ starts a new post.

~reddigg-ping~ checks that the server is up and a Reddit tab is connected.

~reddigg-server-start~ starts the server explicitly and waits until it is ready.

~reddigg-server-stop~ stops the server if Emacs started it.

~reddigg-refresh-session~ reloads the logged-in username after a login change.

~reddigg-show-images~ downloads and shows the images of the entry at point.

~reddigg-toggle-images~ shows or hides inline images in the current buffer.

~reddigg-play-video~ plays the video of the entry at point.

~reddigg-clear-image-cache~ deletes all cached images.

* Read posts

1. Run ~reddigg-view-main~.
2. Select a subreddit.
3. Select a post.
4. Enter on ~view comments~ to open its comments.

* Reddit links

Reddit post links open in reddigg instead of a web browser, wherever
they go through ~browse-url~: org links, eww, =M-x browse-url-at-point=,
and so on. This works for comment permalinks such as
=https://www.reddit.com/r/emacs/comments/lfww57/title/=
(with or without the =www= or =old= subdomain, with tracking query
strings, and with or without the title slug) as well as =https://redd.it/=
share links.

The handler is registered in ~browse-url-handlers~ as soon as the
package is installed; reddigg itself is only loaded when you follow a
matching link. To hand those links back to your browser, remove the
entry pointing at ~reddigg-open-url~ from ~browse-url-handlers~.

Run ~M-x reddigg-open-url~ to paste a link by hand.

* Images

reddigg shows images attached to image posts and galleries, both in
the post list and in the post at the top of the comments buffer.

By default images are downloaded in the background and displayed
inline. The download uses a Reddit preview no wider than
~reddigg-image-max-width~ (default 400 pixels) instead of the
original, which keeps large photos cheap.

Images are cached in ~reddigg-image-cache-dir~ (default
=~/.cache/reddigg/images=), so refreshing a listing does not download
them again. Enter on an image's =file:= link to open it in Emacs.

Use these keys in a reddigg buffer:

- ~C-c C-v i~: download and show the images of the entry at point.
- ~C-c C-v I~: show or hide inline images in the buffer.

~reddigg-image-display~ controls the automatic behavior:

- ~inline~ (the default): download in the background and show the image.
- ~link~: show a ~show image~ button; download only when you use it.
- ~nil~: do not download or show images.

#+begin_src emacs-lisp
(setq reddigg-image-display 'link)
#+end_src

Image data comes from Reddit's public preview/image hosts, not from
the browser session. Set ~reddigg-image-display~ to ~link~ or ~nil~
if you do not want reddigg to contact those hosts automatically.

~reddigg-clear-image-cache~ deletes the cache.

* Videos

Video posts have no image of their own, only a poster frame that
Reddit computes for them. reddigg shows that poster exactly like an
image: downloaded in the background, cached, and displayed inline.

The poster is the same Reddit preview used for image posts, so it is
no wider than ~reddigg-image-max-width~ and costs one small download.
When no preview is available the small =redditmedia= thumbnail is used.

A play badge is drawn onto the poster, the way [[https://github.com/zevlg/telega.el][telega]] marks its
videos: a white triangle in a black circle, baked into a small SVG
file stored next to the cached poster. Org displays that file as a
single image, so scaling and the inline image commands keep working.
Set ~reddigg-video-poster-badge~ to ~nil~ to show the plain poster.
The badge needs librsvg (and Emacs 28 or later); without it reddigg
falls back to the plain poster.

Below the poster is a play link, with the video length when Reddit
reports it:

#+begin_example
[[elisp:(reddigg-play-video)][▶ play video (1:30)]]
#+end_example

Use these keys in a reddigg buffer:

- ~C-c C-v v~: play the video of the entry at point.
- ~C-c C-v i~: download and show the poster of the entry at point.
- ~RET~ or a mouse click on the poster: play the video.

The poster keeps the usual image keys (zoom, rotate), so it stays an
image you can inspect; only ~RET~ and the click are redirected to the
player. Right-clicking the poster still opens the poster file itself.

~reddigg-play-video~ hands the video URL to ~reddigg-video-player~
(~mpv~ by default) and only falls back to ~browse-url~ when that
program is not installed. The player streams the URL; nothing is
downloaded before playback starts.

~reddigg-video-player-args~ adds arguments in front of the URL:

#+begin_src emacs-lisp
(setq reddigg-video-player-args
      (list "--no-terminal" "--demuxer-readahead-secs=5"))
#+end_src

The player runs detached, and its error output goes to the
~*reddigg-video*~ buffer. When it exits with an error, the tail of that
output is shown in the echo area, so an expired URL, a missing codec or
a refused connection does not just close the player window silently.

Hosted videos have two streams: an HLS playlist that carries both
video and sound, and a silent DASH =mp4= fallback. Players get the HLS
playlist; browsers get the =mp4=, because browsers cannot play an
=m3u8= through ~browse-url~.

Videos hosted elsewhere (YouTube and friends) have no Reddit stream, so
the play link passes their own URL to the player.

The entry records what it found in its properties:

#+begin_example
:REDDIGG_IMAGES: <poster URL>
:REDDIGG_POSTER: <poster URL>
:REDDIGG_VIDEO: <HLS playlist, or DASH fallback>
:REDDIGG_VIDEO_FALLBACK: <DASH fallback>
:END:
#+end_example

* Vote

Use these keys in a ~reddigg~ buffer.

- ~C-c C-v u~: upvote.
- ~C-c C-v d~: downvote.
- ~C-c C-v 0~: clear the vote.

The score updates in the current buffer.

* Reply

1. Place point on a post or comment.
2. Press ~C-c C-v r~.
3. Write the reply.
4. Press ~C-c C-c~ to send it.
5. Press ~C-c C-k~ to abort.

The new comment appears under its parent.

* Edit

1. Place point on your post or comment.
2. Press ~C-c C-v e~.
3. Edit the text.
4. Press ~C-c C-c~ to save it.
5. Press ~C-c C-k~ to abort.

~reddigg~ rejects edits for content from another user.

Link posts do not have editable post text.

* Delete

1. Place point on your post or comment.
2. Press ~C-c C-v x~.
3. Confirm the delete prompt.

~reddigg~ rejects deletes for content from another user.

* Submit a post

1. Run ~reddigg-submit-post~.
2. Enter the subreddit name.
3. Select ~self~ or ~link~.
4. Enter the post title.
5. Write the post body or link URL.
6. Press ~C-c C-c~ to submit.
7. Confirm that you want to view the new comments.

For a ~self~ post, enter the post text.

For a ~link~ post, enter the link URL.

~reddigg~ reports the new post ID and URL after a successful submit.

* Compose buffers

~reddigg-compose-mode~ handles reply, edit, and submit buffers.

Press ~C-c C-c~ to send the current compose buffer.

Press ~C-c C-k~ to abort the current compose buffer.

* Reddit session

Write actions use the Reddit session in the userscript tab.

The userscript reads the CSRF token and username from the Reddit page.

~reddigg-refresh-session~ refreshes these values after a login change.

* Remarks

~reddigg~ uses the Reddit API through the userscript running inside the Reddit tab.

Keep the Reddit tab open and logged in while you use ~reddigg~.

For a complete Reddit client, see [[https://github.com/ahungry/md4rd][md4rd]].

* Tests

The ERT tests live in ~test/reddigg-test.el~. They need ~promise~, ~ht~, and ~dash~ on ~load-path~; the file's commentary has the command to run them.
